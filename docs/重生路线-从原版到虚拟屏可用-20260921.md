# 🧭 重生路线：从原版 Operit 到虚拟屏可用（2026-09-21）

> 本文回答三个问题：
> ① 为什么「原版安装的 Operit」虚拟屏点了没反应、用不好？
> ② 我们改了 / 加了什么，把它变成「能用且好用」？
> ③ 备份全没了时，如何按路线再走一遍（含换设备复刻要点）。
> 用途：发给任何「失忆的 AI」/ 交给其他玩家 / 自己留底。操作版配套：kit/README-恢复说明.md。

## 0. 一屏结论
- 原版问题的根，不是操作错误，而是 **Android 17 + 荣耀 ROM 的兼容性**：虚拟屏里一切点击 / 滑动注入失败 → 「点了没反应」的假屏。
- 修复 **不改 APK、不用 root**：给运行时加载的 `shower-server.jar` 打补丁 + 配守护脚本；全部资产住在 `/sdcard` 与 `/data/local/tmp`，卸载重装不丢。**原版安装包照装即可。**
- 当前达成：**点得有效、看得见、开得快、不闪不空、防覆盖、可体检、可一键恢复。**

## 1. 环境基线（参考设备）
- 设备：荣耀 BKQ-AN10 / MagicOS / Android 17；Operit v1.12.2（安装包备份：/sdcard/Download/Operit/operit.apk）
- 权限通道：无 root；Shizuku（shell uid=2000）
- 适用性：不同 Android / ROM 的适配点见 §6；原理与路线通用

## 2. 原版为什么「不能正常用」（按发现顺序）
### 2.1 致命：点击 / 滑动全部无效（假屏）
- 根因①：`InputManager.getInstance` 在 **Android 17 被删除** → 注入调用直接失效（「安卓 17 不兼容」的直觉是对的）
- 根因②：荣耀 ROM 的 `IInputManager$Default.injectInputEventToTarget` **参数顺序与 AOSP 相反**（实际要求 `(displayId, event)`）→ 注错屏 / 无效
- 现象：按钮不按下、界面不变、操作全部无效
### 2.2 致命：AI 看不到虚拟屏（截图错屏）
- 虚拟屏任务请求截图时拿到的是主屏内容 → AI 瞎操作
### 2.3 体验：打开慢 / 空屏干等
- 建屏本身 ~75ms 就绪，但 AI 磨蹭 16~204s 才把 APP 启动进屏
### 2.4 体验：空白 / 黑闪 / 花屏
- 空白自愈失效（v6~v8 的扫描器实为坏件、条件分支错位）→ v9 真修复
- 黑闪约 1.5s 一次：v9「每 60 帧永久重发」节奏所致 → v9.1 窗口化修复
### 2.5 顽固：补丁每次启动被「吞」
- Operit 每次启动 / 更新都用自己的原版 jar（1133303B）覆盖副本 → 不守护 = 白改
### 2.6 残留：孤儿卡 / 黑面死窗（客户端缺陷 · 已搁置）
- 孤儿卡 = 进度卡「清一半」（removeView 未成功）；黑窗 = 流断后窗口不销毁
- 用户决定不动 Operit 本体；缓解：重启一次 Operit 即清；修复设计已存档（《阶段收口-卡片与黑窗》）

## 3. 修复体系（做了什么）
### 3.1 服务端补丁链（核心 · shower-server.jar）
| 版本 | 修什么 | 要点 |
|---|---|---|
| v3 | 注入修复 | 参数序修正 + Android 17 兼容（1162761B） |
| v4 | 截图纠偏 | 请求主屏截图 → 重定向到活跃虚拟屏（1162878B） |
| v6 | 触控 / 空白竞态 | 过渡版（留下「日志标记 ≠ 机制生效」的教训） |
| v9 | 空白自愈真修复 | 重写 NAL 扫描器 + 缓存守卫 / 重发判定（1163819B，md5 038be08b…） |
| v9.1 ★当前基线 | 黑闪修复 | 窗口化重发：前 6 次保护、360 帧后静默（1163846B，md5 e8c1b771…） |

- 部署位：两处副本（数据侧 + `/data/local/tmp`），由看门狗保真；历史版本与回滚脚本齐全（`rollback_to_v9.sh` 等）
### 3.2 看门狗 watchdog —— 补丁保真
- 0.05s 巡检；发现被原版覆盖 → 秒级夺回（`wd_guard.log`：`A fix DL/TMP(sz:1133303->1163846)`）
### 3.3 抢跑哨兵 prewarm_watcher（+ guard_prewarm 看护）—— 加速
- 监听 `shower.log` 的 `Created virtual display id=` → 从 logcat 抓当前 PhoneAgent 任务 → `prewarm_map.tsv` 关键词映射包名 → 写 `prewarm_target.txt`
- 服务端补丁（x.smali）读到后 **自动预启动目标 APP** → 「舞台秒级就绪」
- v5.1：agentId 正则修复（数字 / 下划线开头 token 不再漏判）；看护 20s 巡检，哨兵掉线自动拉起
### 3.4 体检 + 一键恢复 + 冷备份
- `hc.sh` 全身体检（基线 PASS=19 FAIL=0）；`restore_chain.sh`「缺什么补什么」（幂等安全）；`kit/`＝1.1GB 冷备份 + 四场景说明书
### 3.5 配套：任务模板（防乱找路 / 防呆）、急救卡、appscan 认名链（118 应用 / 133 预启动条目）

## 4. 重生路线（四种情形）
### 情形 A · 只是重启了设备
- `sh /data/local/tmp/hc.sh` → 有 FAIL → `sh /sdcard/Download/Operit/restore_chain.sh`
### 情形 B · 更新了 Operit（覆盖安装）
- 看门狗会自动夺回 jar（秒级）→ `hc.sh` 复核 → 仍不对 → `restore_chain.sh`
- 大版本协议变化（黑屏 / 不出画面）→ 走情形 D
### 情形 C · 重装了 Operit（数据清空）
1. 装回 Operit（同版 1.12.2 = 无需重打补丁；或用 operit.apk）
2. GUI 授权：Shizuku / 无障碍 / 悬浮窗 / 电池白名单；权限级别设 DEBUGGER/ADB；开「实验性虚拟屏」
3. 恢复「包 / 技能」：`kit/packages/` → `/sdcard/Android/data/com.ai.assistance.operit/files/packages/`，App 内刷新
4. （若 Ubuntu 环境也没了）重建 Ubuntu 环境（apt 装 openjdk-17 等）
5. `sh /sdcard/Download/Operit/kit/restore_from_kit.sh` → `sh restore_chain.sh` → `hc.sh`（基线 PASS=19 FAIL=0）
### 情形 D · 大版本后「重打补丁」（或从零重走）
1. 从新版 APK 提取 `assets/shower-server.jar`
2. baksmali 反编译（工具在 kit/tools；命令示例见 kit/README-恢复说明.md §D）
3. 依序套补丁：`patch_v6_j.py → patch_v7_j.py → patch_v8_j.py → patch_v9_j.py → patch_v9_1_j.py`（配合 `v*_newb.smali` / `v9_helper.smali`），`make_jar_v9_1.py` 打包
4. 产物 `shower-server-v9.x-new.jar` → 放入 `kit/jars/` 与 `/sdcard/Download/Operit/`
5. 更新 `watchdog.sh` / `restore_chain.sh` 的 SRC 指向、`hc.sh` 顶部基线 md5
6. `restore_chain.sh` + `hc.sh` + 实机验证（§5 绿灯）

> **连 kit 也没了？** 按 §2/§3 的「根因 → 修什么」骨架重新推导。五个核心目标：
> ① 注入参数序 / Android 17 兼容修复 ② 截图重定向到活跃虚拟屏 ③ NAL 扫描器 + 缓存 / 重发修正 ④ 窗口化重发（黑闪）⑤ 读 `prewarm_target.txt` 预启动。
> （这是全项目最关键的「重新发现骨架」，能省最多弯路；其余细节本来也是迭代出来的。）

## 5. 验证清单（每步的「绿灯」）
- 注入：虚拟屏里点一下有真实反应；日志 `Binder TAP injected`
- 截图：AI 截图内容 = 虚拟屏画面
- 帧流：`v9: cached SPS/PPS/IDR`、`v9.1: periodic resend done`；目测不黑闪
- 守护：`wd_guard.log` 出现 `A fix DL(sz:1133303->1163846)`
- 哨兵：`prewarm.log` 出现 `task='...' -> prewarm: <包名>`
- 体检：`sh /data/local/tmp/hc.sh` → PASS=19 FAIL=0 HEALTHY
- 残留：`dumpsys` 中 ShowerVirtualDisplay / UIAutomationProgress 匹配数 = 0

## 6. 给别人使用（适配说明）
- Android 13/14/15 可能没有 §2.1 的兼容问题：先实测「虚拟屏里点一下有没有反应」
- 不同 ROM：注入参数序需实测（荣耀是反的）
- 包名映射：用 appscan 脚本按本机重建 `prewarm_map.tsv`
- 边界：不改 APK、不 root、不绕系统安全；补丁只动 shower-server 运行逻辑；随时可回滚
