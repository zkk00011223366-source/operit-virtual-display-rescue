## 2. 设计原理速记（压缩后必读）
- **手（输入注入）**：Android17 `InputManager.getInstance` 兼容问题 → v3 已修。
- **眼睛（每步截图）**：三条路线 ①Shower线（正解）②AIDL无障碍（失败）③普通线（拍主屏）。分流开关 `canUseShowerForInput = isAdbOrHigher && getDisplayId(agentId)≠null`（在 Operit 主程序 classes12）。
- **v4 补丁**：改 `shower-server` 的 `u2/g`（`requestScreenshot(I)[B`）——请求"主屏(id=0)截图"且存在活跃会话时，强制改截虚拟屏。
- **⚠️ 待解疑问（下次实测第一优先）**：此前会话日志显示截图请求**可能根本没走到 Shower 线**（曾出现 "AIDL takeScreenshot failed" → 回退主屏）。瓶颈可能在**客户端路由**而非服务器。下次测试必须同时抓：①`captureScreenshotForAgent` 决策 ②是否出现 `v4 patch` 字样 ③AI 实际截图内容（`cleanOnExit/`）。
- **抢跑哨兵**：监听 `Created virtual display id=` → sleep 4s → `am start --display $ID` → 失败重试6次。（出生 0.1s 就敲门会被拒 "Failed transaction"）
- **看门狗**：Operit 会话开始从 APK 重新释放原版(1133303B)覆盖两副本；看门狗检测尺寸≠1162878 → 秒级还原。战报见 `wd_guard.log`。
- **⚠️ 毫秒竞态**：会话启动瞬间存在"覆盖→还原"竞态（实测：18:30:23.477 覆盖、.509 还原、服务器 .657 启动——窗口 ~0.15s）。**实测结果：看门狗胜出**——18:30服务器加载的正是 v4版（内存验尸：dump含 “v4 patch” 字符串；证据 `srv_dex_dump.bin`）。如遇异常再考虑加固（inotifyd即时还原）。
- **显示ID冷知识**：虚拟屏系统 id 递增（33/34/35…）；名称形如 `ShowerVirtualDisplay-<内部编号>` —— **名字里的数字不是 id！**（display35 名字叫 "ShowerVirtualDisplay-128"）。shell 的 `screencap -d <虚拟屏id>` 在本机**不可用**（报 not valid）；仅 Operit/服务器 DisplayCapture 能抓虚拟屏。
- **教训·杀进程别用模式匹配**：`ps|grep 模式|kill` 会匹配到自己命令行 → 自杀（exit143 实测踩过）。用**精确 PID**。
