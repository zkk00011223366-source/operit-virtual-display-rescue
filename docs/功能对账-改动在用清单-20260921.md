## 二、三条实锤（为什么说「在干活」）

### ① 看门狗在替你挡刀（最重要）
你重启 Operit 后，官方应用每次都用原版 jar（1133303B）覆盖回来，看门狗随即把补丁版（1163846B）夺回。

→ 你看到的「正常」里，有一部分正是它在对抗官方覆盖。**没有它，补丁重启一次就没了。**

### ② v9.1 补丁在帧链路上实时输出
shower.log（你测试期间）实况：
- `10:50:35.092 v9.1: periodic resend done`

→ 补丁代码在跑的直接指纹；原版 jar 不会有这些日志。

### ③ 抢跑哨兵：诚实账 + 修复复验

## 三、「重启后正常」与「没用到」的关系

1. 补丁是安静型：不改界面，只让画面更稳、并后台保护 jar；平时无感，撤掉才见差别。
2. 看门狗在挡刀：官方每次覆盖被它夺回，你感知不到过程，只看到「正常」。
3. 卡/登录提示/黑屏卡死 = 进程内残留状态，重启即清；属客户端修复范围（已搁置），再犯用「重启一次 Operit」兜底。

## 四、如果完全没改（反事实）

1. 重启后官方原版 jar 长期在线 → 无关键帧缓存/窗口化重发 → 虚拟屏更花、更易黑闪/卡。
2. 哨兵带病 → 每次任务冷启动 App，首屏更慢（「打开速度慢」方向之一）。
3. 没有 kit → 一次更新/重装 = 补丁流水线+工具链+19 个脚本全丢（原本只住在应用数据里）。
