### 矛盾点（实锤）
- 三个 run 均正常走到 `run: finishing, restoring UI`（08:40:51 / 08:42:02 / 09:47:38）
- 但卡窗口 `24be6ab` 从 08:58 存活至 10:07 —— 收尾没有把卡收掉
- 且卡的 X 失效（cancelCallback 已为 null）：与 `hide()` “清完回调、removeView 未成功/被跳过”的半执行表现一致（最可能：removeView 抛异常被吞，或 lifecycle 步骤异常导致跳过 removeView）

### 修复设计（两处）
1. **加固 `hide()`**：`removeView` 单独 try + 失败降级（重试/置不可见），状态清理放最后；避免“回调空、窗口残”的半残状态
2. **收尾收卡**：虚拟屏任务在 “restoring UI” 路径无条件收掉主屏卡；（可选）在 show/update 调用点加 shower 门禁做双保险

## 六、修复验收标准（用户确认版 · 2026-09-21 10:35）
- **A. 虚拟屏任务：主屏卡"从始至终不出现"**（不需要"先出现再关掉"；虚拟屏任务只用自己的窗口内状态栏）。
- **B. 主屏任务：卡允许出现，但任务结束必须"随之一起消失"**（正常结束 / 异常结束 / 被取消，都不允许残留孤儿卡）。
- 对应补丁面：① 虚拟任务在主屏卡所有 show/update 入口加门禁（改走虚拟屏自身状态栏）；② `hide()` 收尾加固（`removeView` 独立保护 + 失败降级 + 状态清理后置，消除"清了一半"的半残状态）；③ 所有结束路径（正常/异常/取消）强制收卡。
- 两条需求同根：均为"关键时刻的清理没走干净"，合并为一套补丁实施。
